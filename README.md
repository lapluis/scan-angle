# scan-angle

本地批量检测扫描图片偏角的工具。根据纸张边缘、边框或其他长直线估算倾斜角度，给出转正建议，并输出终端表格、CSV/JSON 结果和红色标线预览。所有处理在本地完成，原图不会被修改。

Rust 实现，提供桌面窗口界面和命令行入口，也可以构建完全不依赖窗口组件的命令行版本。

## 功能

- 窗口界面与命令行两种入口；命令行支持对齐表格和 `--json` 输出。
- 支持 TIFF（含多页）、PNG、JPEG、BMP、WebP。
- 支持遍历子文件夹，损坏图片记录失败后继续处理。目录列表无法读取时整批报错，避免将不完整扫描标记为完成。
- 窗口进度条按已处理文件数推进，显示“已处理 / 总数”；多页 TIFF 按一个文件计，读取失败文件也计入已处理数。
- 每页输出偏差角、建议转正角、证据一致性状态；保存结果时额外生成标线预览。
- 默认检测 ±15°，可调整到 ±30°。
- 先合并共线短线段，再按方向相关的可配置最短直线阈值筛选（水平线相对分析图宽度，竖直线相对分析图高度），因此虚线、断线中单独较短的片段也可能组成有效长线。
- 可配置分析图最长边和缩放算法；默认不放大原图。
- 合并的角度差、垂直距离和间隙容差均可配置，距离与间隙同时支持“短边百分比 + 绝对像素下限”。

## 环境要求

- **运行预编译程序**：Windows x64 可执行文件，不需要 Python、uv、OpenCV 或其他运行时。
- **从源码构建**：Rust stable 1.88 或更高；Windows 构建还需要 MSVC C++ 构建工具（CI 在 Windows 上验证）。
- **生成测试图片**：需要 Python 3.14 和 uv；仅在开发测试时使用，运行应用本身不需要。

## 快速开始

### 获取程序

仓库目前没有 GitHub Release 或 tag。CI 在每次 push/PR 时执行测试和 Release 构建，并保存 Windows x64 可执行文件：

1. 打开 [Tests 工作流](https://github.com/lapluis/scan-angle/actions/workflows/tests.yml) 最近一次成功的运行。
2. 下载 Artifact `ScanAngle-Rust-windows-x64`，解压得到 `scan-angle.exe`。

也可以从源码构建：

```powershell
cargo build --locked --release
```

生成 `target\release\scan-angle.exe`。构建直接使用 Cargo，不需要 Python、uv 或额外编译脚本。

### 窗口模式

直接运行 `scan-angle.exe`（不带参数）打开窗口。命令行传入的设置会初始化对应控件；选择输入文件夹后，输出文件夹会自动填入输入目录旁的 `<目录名>_角度结果`。

### 命令行模式

```powershell
# 省略 --output：只在终端打印表格，不创建任何文件
.\target\release\scan-angle.exe "D:\workspace\images"

# 保存 CSV、details.json 和预览图
.\target\release\scan-angle.exe "D:\workspace\images" --output ".\results\images"

# 以 JSON 输出到 stdout，不打印表格；加 --output 时仍会写文件
.\target\release\scan-angle.exe "D:\workspace\images" --json

# 包含子目录并调整检测设置
.\target\release\scan-angle.exe "D:\workspace\images" --recursive --output ".\results\images" --max-angle 20 --analysis-size 1600
```

带输入文件夹时执行批处理。命令行省略 `--output` 时，终端以对齐表格逐页显示文件、页码、转正角度、检测 / 合并 / 入选直线数和状态；不会创建输出目录、CSV、JSON 或预览图。

终端输出示例：

```text
文件          页  转正角度（°）  检测 / 合并 / 入选  状态
angle_-2.png   1         +2.000           8 / 8 / 8  可信
blank.png      1              —           0 / 0 / 0  需人工确认
broken.png     —              —           — / — / —  读取失败
```

`--json` 输出一个数组，每个文件/页对应一项，结构与写入文件的 `details.json` 相同。以下为字段节选（省略 `lines`、`merged_lines`、`merge`、`settings` 等字段）：

```json
[
  {
    "angle": -2.0,
    "correction": 2.0,
    "count": 8,
    "file": "angle_-2.png",
    "fragment_count": 8,
    "merged_count": 8,
    "page": 1,
    "status": "可信"
  }
]
```

超过 178,956,970 像素的可信本地图片须显式添加 `--allow-large-images`，窗口也提供对应选项。

### 检测设置

| 设置 | CLI | 默认 | 校验／说明 |
| --- | --- | --- | --- |
| 最大偏角 | `--max-angle` | `15` | 命令行和窗口为 1～30°；用于预筛线段并做最终范围检查 |
| 最短直线百分比 | `--min-line-percent` | `10` | 有限数值，范围 `(0, 100]`；水平线相对分析图宽度，竖直线相对分析图高度 |
| 最短直线绝对长度 | `--min-line-pixels` | `50` | 有限数值，必须大于 0；单位为分析图像素 |
| 分析图最长边 | `--analysis-size` | `2400` | 整数，范围 256～10000；只缩小，不放大原图 |
| 缩放算法 | `--resample` | `lanczos` | `lanczos` / `bicubic` / `bilinear` / `nearest` / `box` / `hamming` |
| 合并角度差 | `--merge-angle` | `0.75` | 有限数值，单位度，范围 `(0, 45)`（不能为 0，也不能为 45） |
| 合并垂直距离百分比 | `--merge-distance-percent` | `0.12` | 百分比：`0.12` 表示 **0.12%**，不是比例 0.12；有限数值，必须 ≥ 0 |
| 合并垂直距离绝对下限 | `--merge-distance-pixels` | `1.5` | 有限数值，必须 ≥ 0；单位为分析图像素 |
| 合并间隙百分比 | `--merge-gap-percent` | `0.5` | 百分比：`0.5` 表示 **0.5%**；有限数值，必须 ≥ 0 |
| 合并间隙绝对下限 | `--merge-gap-pixels` | `6` | 有限数值，必须 ≥ 0；单位为分析图像素 |

有效最短直线长度在合并之后按合并直线的方向分别计算，两者都取百分比长度与绝对像素的较大值：

```text
水平直线：max(min_line_pixels, min_line_percent / 100 × 分析图宽度)
竖直直线：max(min_line_pixels, min_line_percent / 100 × 分析图高度)
```

例如分析图为 1000×4000（宽×高）且使用默认 `min_line_percent=10`、`min_line_pixels=50` 时，水平阈值为 `max(50, 100) = 100` 分析像素，竖直阈值为 `max(50, 400) = 400` 分析像素。若默认 `analysis_size=2400` 将这张图缩小为 600×2400，则按实际分析尺寸计算：水平 `max(50, 60) = 60`、竖直 `max(50, 240) = 240` 分析像素。阈值始终使用缩放后的实际分析图尺寸，不是原图尺寸，也不是请求的最长边设置；由于不放大原图，小图的分析图尺寸就是原图尺寸，阈值也会相应变小。设置在任何批处理开始前统一校验，NaN、无穷大、越界整数和未知缩放算法都会被拒绝。

### 合并容差

合并容差同样使用**缩放后的实际分析图短边** `short = min(分析图高度, 分析图宽度)`：

```text
有效垂直距离容差 = max(merge_distance_pixels, short × merge_distance_percent / 100)
有效投影间隙容差 = max(merge_gap_pixels, short × merge_gap_percent / 100)
```

百分比输入始终按百分数解释：`0.12` 是 0.12%，不是 12%，也不是比例 0.12。距离和间隙的百分比与绝对下限都允许为 0，且没有额外的任意上限，只要求有限且非负。

- 默认短边为 2400 像素时：距离 `max(1.5, 2400 × 0.12 / 100) = max(1.5, 2.88) = 2.88` 像素，间隙 `max(6, 2400 × 0.5 / 100) = max(6, 12) = 12` 像素。
- 短边为 600 像素时：距离 `max(1.5, 0.72) = 1.5` 像素，间隙 `max(6, 3) = 6` 像素，两个绝对下限生效。
- 例如 `--merge-distance-pixels 2 --merge-gap-percent 1` 在短边 1000 像素时，距离为 `max(2, 1000 × 0.12 / 100) = max(2, 1.2) = 2` 像素，间隙为 `max(6, 1000 × 1 / 100) = max(6, 10) = 10` 像素（间隙默认下限仍为 6，除非同时设置 `--merge-gap-pixels`）。

**零容差语义：** `merge_distance_percent` 与 `merge_distance_pixels` 同时为 0 时，有效距离容差为 0，只有两个端点都**精确**落在锚定直线上的片段才会合并；`merge_gap_percent` 与 `merge_gap_pixels` 同时为 0 时，有效间隙容差为 0，投影区间必须重叠或恰好相接，任何正间隙都会把链拆开。代码不会用 epsilon 把 0 悄悄替换成非零容差。角度容差则必须严格大于 0 且小于 45 度，0 和 45 都会被拒绝。

## 输出与结果

### 终端表格

命令行省略 `--output` 时，只输出对齐表格，不写文件。列为：文件、页、转正角度（°）、检测 / 合并 / 入选、状态。

- “转正角度”与偏差角度符号相反；正数表示顺时针。
- “检测 / 合并 / 入选”依次为进入合并的线段数（`fragment_count`）、最短长度筛选前的合并直线总数（`merged_count`）、最终参与角度估算的直线数（`count`）。
- 读取失败时显示 `—`、`— / — / —` 和“读取失败”。

### JSON 输出

`--json` 在 stdout 打印 JSON 数组，结构与 `details.json` 相同；每条记录包含检测结果、合并诊断信息和设置。它不会打印表格，也不会在未指定 `--output` 时写文件。

### 写入文件

指定 `--output` 或使用窗口保存结果时，输出目录中包括：

| 文件 | 内容 |
| --- | --- |
| `angles.csv` | 每张图片、每页的检测结果，UTF-8 BOM，可用 Excel 打开 |
| `details.json` | 检测角度、合并后直线坐标、本次设置与合并诊断信息 |
| `previews/` | 蓝色细线绘制全部合并直线，红色粗线突出最终入选直线 |

`angles.csv` 中“合并直线数”及 `details.json` 中的 `count` 是**合并、筛选后参与角度共识的直线数量**，预览红线对应这些入选直线。窗口“直线数”列显示 **检测 / 合并 / 入选**：依次为进入合并的线段数（`fragment_count`）、最短长度筛选前的合并直线总数（`merged_count`）、最终参与角度估算的直线数（`count`）。读取失败时显示 `— / — / —`。预览先以蓝色细线绘制全部合并直线，再以红色粗线覆盖入选直线；没有入选直线时仍绘制蓝色合并直线。

`details.json` 每条记录包含：

- `settings`：本次运行的原始设置，包括最大偏角、最短直线百分比／像素、分析图最长边、缩放算法，以及 `merge_angle`、`merge_distance_percent`、`merge_distance_pixels`、`merge_gap_percent`、`merge_gap_pixels` 五个合并设置。
- `fragment_count`：排除图像边框和目标角度范围后，进入合并的原始线段数。
- `merged_count`：合并后的直线数（应用最短长度筛选之前）。
- `merged_lines`：上述全部合并直线的坐标及诊断数据，与预览蓝色底层对应。
- `thresholds_px`：按方向区分的有效最短直线长度，例如 `{"horizontal": 100.0, "vertical": 400.0}`；水平对应分析图宽度，竖直对应分析图高度。
- `merge`：本次图片按实际分析尺寸计算出的有效合并容差，包括 `angle_tolerance_deg`（度）、`perpendicular_tolerance_px`（垂直距离，分析像素）、`gap_tolerance_px`（投影间隙，分析像素），以及原始、合并、入选数量。即使设置为 0，这里也记录真实的 0，而不是替换值。
- `lines`：入选的合并直线，含 `support_length`（去重后的实际支撑长度）、`span_length`（首尾跨度，包含未观测间隙）、`gap_length`、`member_count` 和方向。

读取失败的文件或页也会写入 `details.json`，并保留本次设置和错误说明。

**偏差角度正数表示顺时针倾斜，负数表示逆时针倾斜。** 建议转正角度采用同一符号约定，与偏差角度符号相反。例如偏差 `+1.724°`，表示建议逆时针旋转约 `1.724°`。

“可信”表示多条分离直线的方向较一致，是启发式判断，并非概率或测量精度保证。“需人工确认”可包含参考角度；角度空白表示没有足够证据。角度输出三位小数便于比较，并不意味着实际精度达到千分之一度。

每次运行会覆盖所选输出目录中的 CSV、JSON 和同名预览。建议不同批次使用独立输出目录。输出目录不能与输入目录相同，也不能是输入目录的上级目录；输入目录内的输出子目录会自动排除。

窗口界面不受“省略 `--output`”规则影响：选择输入文件夹后仍会自动填入输入目录旁的 `<目录名>_角度结果`，并将结果写入该目录。

## 直线合并

处理顺序是：EXIF 方向归一化 → 缩放为分析图 → Rust LSD 提取线段 → 排除贴近图像边框的线段和超出最大偏角的线段 → **合并共线片段** → 按方向相关的有效最短长度筛选 → 角度共识。

合并规则：

- 水平方向和竖直方向分别处理。二者归一化后的偏角可能都是 0°，但绝不会互相合并。
- 端点顺序会先统一，因此反向输入的线段等价。
- 允许重叠和断开的片段；重叠部分只计一次，未观测的间隙不计入支撑长度。
- 合并容差（分析图像素，短边 = `min(高, 宽)`）：
  - 方向角差 ≤ `merge_angle`（默认 `0.75°`，必须严格位于 `(0, 45)`）；
  - 其他片段两个端点到锚定直线的垂直距离 ≤ `max(merge_distance_pixels, 短边 × merge_distance_percent / 100)`；
  - 相邻片段投影区间之间的间隙 ≤ `max(merge_gap_pixels, 短边 × merge_gap_percent / 100)`。
- 默认 2400 像素短边时，垂直容差约 `2.88` 像素，间隙容差 `12` 像素。百分比按 0.12% / 0.5% 解释，不是比例；距离和间隙的百分比与像素下限都允许为 0（零表示精确共线／仅重叠或相接），角度不允许为 0 或 45。
- 每次取剩余片段中最长的一条作为稳定锚定直线，其他片段必须同时满足方向、角度和**两个端点**到该锚定直线的垂直距离条件；所有成员都直接对照最终锚定线复核，容差不会沿着链条逐段放大。
- 通过锚定检查的片段投影到锚定方向上，相邻投影区间间隙不超过容差即视为连通；与锚定片段处于同一连通分量的整条链一次成组，因此任意长度的共线断线都能恢复，且不受片段相对长度或输入顺序影响。
- 该组移除后再取剩余片段中的最长者作为下一组锚定线，结果确定且与输入顺序无关。逐个相邻片段都“勉强接近”的链条仍不会逐渐漂移成另一条线。

合并后的角度取各片段方向的去重加权平均，直线位置取支撑片段中点的去重加权位置；坐标跨度覆盖所有支撑片段。用于阈值和角度权重的 `support_length` 是投影区间的并集长度；阈值按合并后直线的方向选择（水平用分析图宽度、竖直用分析图高度），因此：

- 重叠片段不会重复计权；
- 片段之间的大间隙不会被当作已观测证据；
- 单个片段都短于阈值时，只有合并后的实际支撑长度达到阈值才会入选；
- 窄边方向的直线不会因为另一方向很长而被过高阈值错误淘汰，宽边方向的直线也不会因为过低阈值误收。

超过间隙容差的两段不会合并，也不会为了凑长度而填满中间空白。

## 方法和限制

图片先按 EXIF 方向归一化，再按所选算法缩小为最长边不超过分析图设置的分析图（不放大）。使用纯 Rust lsdetect 直线段检测器提取线段；排除图像边框后，按水平和竖直方向分别合并共线片段，再按方向相关的最短长度和最大偏角筛选。最后按支撑长度加权寻找一致角度簇并计算加权中位数，结合空间上分离的直线数量、角度离散和竞争方向标记结果状态。

适合纸边、边框、表格线较清楚的扫描图。圆形光盘、无直线插画、浅色边缘、弯曲或透视变形可能无法可靠判断。画面内容中的设计斜线也可能影响结果，应核对预览。

合并是启发式处理：

- 间距小于垂直容差的两条平行边可能被视为同一条线（通常对应同一条粗线的两侧）；不同物理线条应保持更大的间距。
- 间隙大于容差或点间距过大的虚线不会被连接，可能因单段长度不足而不输出角度。
- 有效容差以分析图像素计，并按实际分析图短边缩放，因此修改 `--analysis-size`（或原图尺寸）会同时改变可合并的间隙和垂直距离；需要跨批次严格一致时请固定分析图尺寸及合并设置。
- 合并只依据几何关系，不判断语义；正文中的短横线、表格装饰线仍可能参与估算，请核对预览。

当前版本只检测偏角，不执行图像转正，不判断文字的 90°/180° 正反方向，也不做透视矫正，不自动旋转。

## 开发

### 模块结构

- `detection.rs`：检测设置、线段合并和角度共识。
- `imaging.rs` / `resample.rs`：图片读取、分析图缩放和六种缩放滤镜。
- `batch.rs`：批量遍历、逐页处理、CSV/JSON 报告和预览输出。
- `report.rs`：命令行结果表格的列宽计算与对齐。
- `cli.rs` / `gui.rs`：命令行和窗口入口。
- `main.rs`：GUI/批处理分发和命令行输出。
- `multiframe.rs`：APNG 默认帧和 MPF JPEG 的元数据发现。
- `wic.rs`：Windows 内置 TIFF 编解码回退。
- `Cargo.lock` 纳入版本控制，构建和测试均使用 `--locked`。

### 测试

```powershell
uv run --locked scripts/generate-fixtures.py
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

根目录的 `pyproject.toml`、`uv.lock` 和 `.python-version` 管理测试环境。安装 uv 后，上述 `uv run --locked` 会准备 Python 3.14 和固定版本 Pillow 12.3.0；它们仅用于生成独立参考图片，不是 Rust 应用的运行或编译依赖。仓库只保存生成代码、JSON 基准和 SHA-256 清单，不保存二进制测试图片。生成器会核对全部 55 个文件的校验值，且不会重写基准。

回归样本来自原 Python 版的合成测试：120 组合并基准、24 组检测管线基准、11 张已知角度／断线／空白／圆形图，以及 30 个格式与 EXIF 样本。合并与检测管线逐字段对照；独立 LSD 实现允许细微线段差异，合成图角度误差须在原测试的 0.12° 内，分类须一致。测试还覆盖全部参数、GUI 初始化、非法输入、递归输出排除、逐文件进度、逐页失败记录、CSV BOM 和 JSON 结构。测试仅使用合成图片，不访问用户扫描文件或网络。

算法并非逐像素复刻 Pillow/OpenCV，原始线段数量和预览压缩像素可能不同。设置含义、输出字段、合并规则和置信度判据保持一致。迁移记录见 [docs/rust-migration.md](docs/rust-migration.md)。

### 无 GUI 构建

默认构建同时包含窗口和命令行。若只需批处理（例如服务器、计划任务或 CI 环境），关闭默认的 `gui` 特性即可构建完全不链接窗口组件的版本：

```powershell
cargo build --locked --release --no-default-features
```

生成 `target/release/scan-angle.exe`。该版本使用控制台子系统，不依赖 `eframe`、`rfd`、`open` 或图形会话；运行时必须提供输入文件夹，缺少文件夹会打印用法并以退出码 2 结束，不会尝试打开窗口：

```powershell
# 结果保存到文件
.\target\release\scan-angle.exe "D:\workspace\images" --output ".\results\images"
# 省略 --output：只在终端打印结果，不写入文件
.\target\release\scan-angle.exe "D:\workspace\images"
```

对应的测试命令为 `cargo test --locked --no-default-features`。需要窗口界面时仍使用默认构建（不带 `--no-default-features`）。

### Windows 构建

```powershell
cargo build --locked
# Release 版本：
cargo build --locked --release
```

分别生成 `target/debug/scan-angle.exe` 和 `target/release/scan-angle.exe`。双击打开窗口，带输入目录则批处理。构建产物不纳入 Git。GitHub Actions 在 Windows 上执行测试和 Release 构建并保存可执行文件 artifact。
